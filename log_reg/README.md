# Porn Detection (Classification)

Задача бинарной классификации текстовых данных - определение нежелательного контента.  
Используются линейные модели поверх TF-IDF признаков с символьными n-граммами.

## Целевая метрика

**F1-score** (macro) - основная метрика качества.  
**Лучший LB score = 0.98607** (LinearSVC)

## Данные

Текстовый датасет с сильной **разбалансированностью классов**:

| Класс | Представителей | Доля |
|-------|-----------------|------|
| 0  | 118 593  | ~87.7% |
| 1  | 16 715 | ~12.3% |

Учёт дисбаланса - один из ключевых факторов улучшения метрик:
- **Стратифицированное разбиение** при кросс-валидации
- **Веса классов(balanced))**: `{0: 0.5705, 1: 4.0475}`

Чеклист подготовки данных:
- [x] Удалены строки с пустым `title`
- [x] Токенизация и лемматизация
- [x] Проверена утечка данных

## Preprocessing

Что дало наибольший прирост (по убыванию значимости):

1. **Учёт разбалансированности классов** - стратификация при сплите + `class_weight` в параметрах модели
2. **TF-IDF** вместо простых счётчиков
3. **`analyzer="char_wb"`** с большим числом фич - символьные n-граммы без выделения пробелов, что позволяет лучше улавливать морфологию слов
4. **Отдельный encoder для URL** - URL-адреса обрабатываются независимо от основного текста. При их обработке используются n_grams длинной до 5 символов, для отлавливания запретных слов, которые присущи только запрещённым сайтам.

## Особенности задачи

- Для признаков используются **символьные n-граммы** (`char_wb`), чтобы формировать подстроки внутри слов без захвата пробелов между ними.
- Выборка **небольшая** - использование `SGDClassifier` с `partial_fit` (батчевое обучение) не даёт преимущества перед обычным `fit`; предпочтительны более простые модели.
- В финальном варианте **features > n_samples**, что теоретически мотивирует использовать байесовские модели.

## Выводы

- Все модели после подбора гиперпараметров показали **сопоставимые метрики** - разница минимальна как по CV, так и по LB.
- Батчевое обучение (`partial_fit`) **не даёт преимущества** на данном объёме выборки.
- Благодаря гибкости `SGDClassifier` на ней одной удалось воспроизвести результаты `LinearSVC` (hinge loss) и `LogisticRegression` (log loss) - просто меняя параметр `loss`.
- Лидер по LB - **LinearSVC (0.98607)**, хотя по CV F1 он разделяет первое место с LogisticRegression.
